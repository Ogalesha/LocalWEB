# Networking

Every project owns a fixed loopback web port in `18000-18999`, rendered as `listen 127.0.0.1:<port>` in nginx and as `Listen`/`VirtualHost 127.0.0.1:<port>` in Apache. Start prints `http://127.0.0.1:<port>`; plain HTTP therefore works even when another local stack holds ports 80 and 443. Both web servers forward PHP to per-project PHP-FPM sockets.

On Linux the HTTPS gateway selects the first free dedicated address from `127.0.0.2` through `127.0.0.254` and binds port 443 there. Exact LocalWeb hostnames resolve to that address, while independent applications remain on `127.0.0.1:443`; neither process is stopped or reconfigured. The normal URL is therefore portless, for example `https://indeks.dev`. A port in `8443-8499` is used only if the standard binding fails, and that fallback is reported by status, project details, Doctor and the GUI. Only the gateway executable holds `CAP_NET_BIND_SERVICE`. The gateway chooses certificates by SNI, validates the Host header and forwards standard proxy headers (`X-Forwarded-Host`, `X-Forwarded-Proto`, `X-Forwarded-For`). LocalWeb adds no HSTS header; applications may return their own. Both `.dev` and `.test` domains are served only through the gateway.

Shared database engines stay on their internal loopback ports (MariaDB `33071`, MySQL `33072`, PostgreSQL `33073`). Each project with a network database gets a fixed proxy port in `19000-19999`; the daemon forwards it to the shared engine, and the project environment exposes it as `DB_HOST=127.0.0.1` with `DB_PORT=<proxy port>`. Redis and Mailpit keep their own loopback ports or private sockets.

The privileged helper writes exact project hostnames into one atomic `/etc/hosts` block. It never configures a `.dev` wildcard. Every hostname maps to the gateway's selected IPv4 loopback address, and the helper rejects every non-loopback address.
